# คู่มือเก็บข้อมูล 32 set สำหรับ eval ของ feedback

> **2026-11-11: เหลือ 32 set (เดิม 36)** · ขอ PDPA ไม่ทัน ระบบจึงไม่รับ medical history แล้ว แถวกลุ่ม "มีประวัติสุขภาพ" ถูกตัด ไม่ต้องทำ · **เลขแถวรันใหม่เป็น 1–32** (ตารางข้อ 5, เว็บตาราง และหน้า `/coverage` ที่ pull หลังวันนี้ใช้เลขเดียวกัน) · set ที่ทำไปแล้วไม่ต้องทำใหม่ set ที่เคยตั้งประวัติไว้จะนับตามท่าผิดเหมือน set อื่น · ถ้ายังไม่ได้ pull ก็เก็บต่อได้ ให้ Medical history เป็น `None` ตามเดิม แต่หน้า `/coverage` ในเครื่องจะยังใช้เลขแถวเก่า 1–36 ให้ดูชื่อกฎกับแบบเป็นหลัก ฝั่ง Sujira นับเป็น 32 ตอนรวมไฟล์ · RAG_SYSTEM ที่ pull หลังวันนี้ไม่ส่ง medical history ให้ model และไม่บันทึกลง capture แม้แอปรุ่นเก่าจะส่งมา

**ขอให้ช่วยอะไร:** ทำ set ตามตารางในข้อ 5 บนแอปในเครื่องของตัวเอง แล้วส่งไฟล์ที่ระบบบันทึกไว้ผ่านเว็บตาราง

**เอาไปใช้ทำอะไร:** ใช้ input จริงจากแอปเป็นชุดทดสอบ RAG vs no-RAG โดยคำตอบที่ใช้ประเมินจะสร้างใหม่ทีหลัง ข้อความ feedback ที่เห็นบนแอปตอนเก็บจึงไม่ถูกนำไปให้คะแนน ถ้ามันแปลกหรือขึ้น error เพราะ Groq ติดโควตาก็ไม่เป็นไร

**ค่าใช้จ่าย:** ไม่มี ใช้ Groq ฟรีเท่านั้น ห้ามใส่ Gemini key แบบเสียเงิน

**แบ่งงาน:** ไม่ได้ล็อกว่าใครทำแถวไหน แต่ละคนทำกี่แถวก็ได้ ดูแถวที่ยังว่างในเว็บตาราง กด **จอง** ก่อนเริ่มเพื่อกันการทำซ้ำ แล้วติ๊กเมื่อเสร็จ เว็บจะบันทึกชื่อไว้ที่แถวนั้น หน้า `/coverage` มีลิงก์มาที่เว็บตารางให้

## 1. เตรียมครั้งเดียวก่อนเริ่ม

**1.1 ติดตั้งให้ครบ** ถ้ายังไม่เคยทำ:
- feedback service: `docs/FEEDBACK_SETUP.md` ของแอป
- similarity service: หัวข้อ similarity ใน `README.md` ของแอป

**1.2 อัปเดตโค้ด 1 ครั้ง** แล้ว**ห้าม pull อีกจนกว่าจะเก็บเสร็จ** เพราะถ้ากฎตรวจท่าเปลี่ยนกลางทาง ข้อมูลจะเทียบกันไม่ได้

```bash
cd MU-Capstone-Application && git pull
cd ../RAG_SYSTEM && git pull
```

**1.3 ตรวจ `.env` ของ RAG_SYSTEM** ต้องมี 2 บรรทัดนี้ ถ้าไม่มีบรรทัดแรก ระบบจะไม่บันทึกอะไรเลย

```
FEEDBACK_CAPTURE=capture/app_requests.jsonl
FEEDBACK_LLM_PROVIDER=groq
```

**1.4 ตรวจ `.env.local` ของแอป** ต้องมีครบ 2 บรรทัด ถ้าไม่มี `SIMILARITY_URL` แอปจะใช้คะแนนปลอม และ set นั้นจะใช้ไม่ได้

```
FEEDBACK_URL=http://127.0.0.1:8100/feedback
SIMILARITY_URL=http://127.0.0.1:8765/score
```

**1.5 สมัครบัญชีใหม่ในแอปสำหรับงานนี้** เพื่อให้ไม่มีประวัติการฝึกเก่าปนมา กรอก profile ดังนี้:

| ช่อง | ค่า |
|---|---|
| ชื่อ | `A`, `B` หรือ `C` โดยตกลงกันให้ไม่ซ้ำ |
| อายุ น้ำหนัก ส่วนสูง เพศ | ค่าสมมติ ไม่ใช้ข้อมูลจริง |
| Medical history (มีเฉพาะแอปรุ่นก่อน 2026-11-11) | `None` |

**ห้ามใส่ชื่อจริงหรือประวัติสุขภาพจริงของใครเด็ดขาด** ชื่ออยู่ในไฟล์ capture ที่ส่งต่อกัน

## 2. เปิดระบบทุกครั้งที่จะเก็บ

เปิดทั้ง 4 ตัวตามลำดับนี้:

1. `npx supabase start` ในโฟลเดอร์แอป
2. `python services/similarity/server.py` ในโฟลเดอร์แอป โดยใช้ Python จาก venv ของ similarity
3. `.venv/Scripts/python -m service` ใน RAG_SYSTEM (Mac: `.venv/bin/python -m service`)
4. `npm run dev` ในโฟลเดอร์แอป

ตรวจก่อนเริ่ม: เปิด `http://127.0.0.1:8100/health` ต้องเห็น `"ok":true` และ `"llm":"groq:qwen/qwen3.8-27b"` ถ้าขึ้น `knowledge base database is not reachable` หลังรอราว 5 วินาที แปลว่ายังไม่ได้เปิด Supabase

## 3. ขั้นตอนต่อ 1 แถว

1. เลือกแถวที่ยังว่าง แถวละ 1 set แล้วกด **จอง** ในเว็บตาราง เพื่อให้เพื่อนเห็น ถ้าเปลี่ยนใจให้กด **ยกเลิกจอง**
2. เริ่ม workout ใหม่ เลือกท่า แล้วตั้ง **Reps per set = 10** และ **Number of sets = 1** (Rest ค่าเท่าไรก็ได้ ท่า curl เลือกแขนข้างใดก็ได้)
3. วางกล้องตาม guide ของแอป เหมือนการใช้งานปกติ
4. ทำท่าและจบ set ตามที่แถวนั้นเขียนไว้
5. รอที่หน้า set-complete จนเห็น feedback หรือข้อความ error
6. กด **Skip it** ห้ามทำ repair set แล้วกด Finish workout
7. เปิด `http://127.0.0.1:8100/coverage` ดูว่า set เข้าแถวที่ตั้งใจไหม ถ้าตรงก็ติ๊กแถวนั้น

## 4. ข้อควรรู้ตอนทำท่า

- กฎที่ตรวจตลอดการเคลื่อนไหว (`rounded_back`, `hip_sag_or_pike`, `forward_trunk_lean`, `elbow_flare`) ต้องค้างท่าผิดต่อเนื่องอย่างน้อย 10 frame จึงควรคงท่าผิดไว้ตลอด rep ไม่ใช่แค่แวบเดียว
- กฎเรื่องความลึกอาจทำให้ rep ไม่ถูกนับ ตัวนับจึงอาจไม่ขึ้น ไม่ได้แปลว่าระบบเสีย ให้นับจำนวนครั้งเอง
- ถ้าทำไปแล้วมีท่าผิดอื่นโผล่เกิน 1 ครั้ง ระบบจะย้าย set นั้นไปแถวอื่นเอง ถ้าแถวที่ตั้งใจยังว่างให้ทำใหม่
- วิธีทำเป็นแนวทางจากเงื่อนไขของกฎ ยังไม่ได้ลองครบทุกกฎกับกล้องจริง ถ้ากฎไหนทำให้ขึ้นไม่ได้ ให้จดในช่องของแถวนั้น อย่าเปลี่ยนวิธีเองแล้วนับเป็นผ่าน

**ถ้าเจ็บหรือรู้สึกไม่ปลอดภัยให้หยุดทันที** ทำท่าผิดแค่พอให้ระบบจับได้ ไม่ต้องฝืน และอย่าใช้น้ำหนักเพิ่ม

## 5. ตาราง 32 set

ทุกแถวคือ 1 set ตั้ง 10 reps × 1 set หมายเลขแถวตรงกับที่หน้า `/coverage` แสดง (`row_numbers` ใน `eval/replay_captured.py`)

**วิธีทำแต่ละแบบ**

| แบบ | ทำอย่างไร | จบ set อย่างไร |
|---|---|---|
| **ผิดตลอด** | ทำผิดอย่างน้อย 7 จาก 10 ครั้ง | ครบ 10 ครั้งแล้วกด **End set** |
| **ผิดตลอดจนแอปหยุด** | ทำผิดอย่างน้อย 14 จาก 20 ครั้ง | ทำต่อจนแอปหยุดเองที่ 20 ครั้ง |
| **ผิดบางครั้ง** | ทำถูก 7 ครั้ง → ทำผิด 3–5 ครั้ง → ทำถูกต่อ | ทำจนได้ท่าถูกครบ 10 ครั้ง แอปจะหยุดเอง |
| **ผิดหลายกฎ** | สลับท่าผิดตามกฎในแถว กฎละอย่างน้อย 3 ครั้ง | ครบ 10 ครั้งแล้วกด **End set** |
| **ไม่ผิดเลย** | ทำถูกทุกครั้ง | ทำจนครบ 10 ครั้ง แอปจะหยุดเอง |

**ท่าผิดของแต่ละกฎ**

| กฎ | ข้อความบนจอ | ท่าผิด |
|---|---|---|
| `partial_squat` | Lower to 90 degrees | ย่อแค่ครึ่งทาง เข่าไม่ถึง 100° |
| `knee_valgus` | Push knees out | บีบเข่าเข้าด้านใน |
| `knee_varus` | Keep knees in line | บานเข่าออก |
| `rounded_back` | Keep back straight | โน้มลำตัวไปหน้าเกิน 45° |
| `hip_sag_or_pike` | Body not straight | ปล่อยสะโพกตก (แถว 13 ยกก้นโด่ง) |
| `partial_pushup` | Lower Your Chest | ลงไม่สุด |
| `shallow_lunge` | Lower your front knee | ย่อตื้น เข่าหน้างอไม่ถึง 105° |
| `excessive_front_knee_flexion` | Raise your front knee | ย่อเข่าหน้าลึกกว่า 70° |
| `forward_trunk_lean` | Keep Torso Upright | เอนลำตัวไปหน้าเกิน 20° |
| `straight_back_leg` | Bend your back knee toward the floor | เข่าหลังเหยียดเกิน 120° แต่เข่าหน้าต้องลงถึง 105° |
| `elbow_flare` | Keep Elbows at Your Sides | กางหรือแกว่งแขนบนออกจากลำตัวเกิน 45° |
| `partial_curl` | Full range of motion | ไม่เหยียดแขนสุดด้านล่าง |

## 6. ตรวจว่าข้อมูลเข้าถูกแถว

เปิด `http://127.0.0.1:8100/coverage` ในเบราว์เซอร์ระหว่างที่ feedback service ทำงานอยู่ ไม่ต้องรันคำสั่ง ไม่เรียก API และไม่เสียเงิน

หน้านี้บอกว่า set ล่าสุดเข้าแถวไหน ถ้าไม่นับก็บอกเหตุผลและสิ่งที่ต้องทำ และนับเฉพาะ set ในเครื่องของตัวเอง set ที่เกินมาไม่ต้องลบ ระบบใช้ set แรกของแถวเป็นชุดทดสอบเสมอ

## 7. ปัญหาที่พบบ่อย

| ที่เห็น | ต้องทำอะไร |
|---|---|
| `language model is busy` | **ไม่ต้องทำอะไร** ข้อมูลถูกบันทึกแล้ว ทำ set ถัดไปได้เลย (Groq ฟรีตอบได้ราวนาทีละครั้ง) |
| `feedback service is not reachable` | **ยังไม่ถูกบันทึก** เปิด feedback service แล้วกด Retry |
| `knowledge base is not reachable` | ข้อมูลถูกบันทึกแล้ว แต่ควรเปิด Supabase ให้เรียบร้อยก่อน set ถัดไป |
| ข้อความลงท้าย `(Stub feedback ...)` | **ยังไม่ถูกบันทึก** แอปไม่เห็น `FEEDBACK_URL` ให้แก้ `.env.local`, restart แล้วกด Retry |
| feedback ดูแปลกหรือพูดผิด | ไม่เป็นไร ไม่นำข้อความนี้ไปให้คะแนน **ถ้าอยากแจ้งปัญหา บอกแค่ว่าเจออะไร** อย่าแก้ prompt เอง |

## 8. ห้ามทำระหว่างเก็บ

- ห้าม `git pull` หรือแก้กฎตรวจท่า, similarity หรือ `.env` ส่วนอื่น
- ห้าม `npm run db:reset` เพราะจะลบประวัติการฝึกและ KB
- ห้ามทำ repair set (ยกเว้น Sujira ขอเพิ่ม)
- ห้ามใส่ข้อมูลส่วนตัวหรือประวัติสุขภาพจริง
- ห้าม commit ไฟล์ใน `capture/` หรือส่งเข้ากลุ่มแชต เพราะ repo นี้เป็น public และไฟล์มีข้อมูล profile (ไฟล์ก่อน 2026-11-11 อาจมีประวัติสุขภาพที่กรอกด้วย)

## 9. เมื่อทำเสร็จ

1. เปิด `http://127.0.0.1:8100/coverage` ดูว่ามี set ที่ไม่นับและต้องทำใหม่ไหม
2. กด **ดาวน์โหลดไฟล์สำหรับส่ง** ในหน้านั้น ไม่ต้องเปลี่ยนชื่อไฟล์
3. ไปที่แท็บ **ส่งไฟล์** ในเว็บตาราง เลือกไฟล์แล้วกดส่ง
4. แถวที่ทำไม่ได้ ให้จดในช่องของแถวนั้นว่าลองแล้วเกิดอะไรขึ้น

ส่งซ้ำได้ ถ้าทำเพิ่มทีหลังก็ส่งไฟล์ล่าสุดอีกครั้ง set เดิมจะไม่ถูกนับซ้ำ รายการไฟล์ที่ส่งแล้วแสดงชื่อในแอปที่อ่านจากข้อมูลในไฟล์ ถ้าไม่ตรงกับบัญชีที่ใช้เก็บ ให้ตรวจว่าส่งถูกไฟล์ไหม

**ฝั่งผู้รับไฟล์ (Sujira):** ไฟล์อยู่ใน asset ของเว็บตาราง รายการอยู่ใน collection `uploads` (ชื่อคนส่งที่พิมพ์เองคือ `by` ชื่อบัญชีจากในไฟล์คือ `app_names`) เก็บลง `capture/<ชื่อ>_<id>.jsonl` แล้วรัน `python eval/replay_captured.py coverage` เพื่อดูภาพรวมทุกคน
